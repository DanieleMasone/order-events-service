Order Events Service

A focused Spring Boot service that persists orders, publishes Kafka events, consumes them idempotently, and exposes generated API and coverage documentation through GitHub Pages.

System Overview

The service exposes one business workflow: create an order, persist it, publish an OrderCreatedEvent, consume that event, and record the processed event ID. The project intentionally avoids distributed-system extras that would obscure the core reliability patterns.

REST API

Validates create-order requests and returns a stable response contract.

PostgreSQL

Stores orders and the consumer idempotency table managed by Flyway.

Kafka

Publishes and consumes order.created.v1 events with DLT recovery.

Quality and Reliability

Idempotency

Each event has an eventId. The consumer records processed IDs and treats duplicate markers as successful no-ops.

Retry and DLT

Transient listener failures propagate to Spring Kafka retry and then to order.created.v1.dlt after attempts are exhausted.

Intentional Scope

Focused reliability

Kafka publication, idempotent consumption, retry handling, DLT routing, and PostgreSQL persistence are the core design surface.

Generated quality signals

OpenAPI documentation, Docker-based local development, CI checks, and JaCoCo reports are generated by Maven and GitHub Actions.

Deliberate exclusions

Transactional outbox, schema registry, distributed tracing, Kubernetes, saga orchestration, and additional microservices are out of scope.

Generated documentation is produced by Maven under target and published from target/pages.
